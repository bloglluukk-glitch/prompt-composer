# 구조와 선택 규칙

**한국어** | [English](ARCHITECTURE.en.md)

요청 JSON → 의도 구조화 → Motion/Redshift 카드 점수화 → 역할별 선택과 파생 의존성 확인 → 문맥에 맞는 프롬프트 조합 → 검수·출처·불확실성 출력.

`data/knowledge.json`은 공개용 카드 23개를 제공하고 `composer_config.json`은 한·영 표현, 순위 가중치, 충돌·의존 규칙과 문맥별 지시문을 제공합니다. 공식 기술 원리와 제작자의 프롬프트 판단은 [출처 안내](../SOURCES.md)에서 구분합니다.

## 선택

직접 의도 표현, 시각 어휘, 명시한 선호와 관계를 점수화합니다. 일반적인 ‘제품·영상·표면’ 같은 어휘만으로 지식을 대량 선택하지 않습니다. 공개판에는 검증된 모델별 적합도 수치를 제공하지 않습니다.

Motion 3개, Material 2개, Lighting 2개, Camera 1개, Atmosphere/Lens 각 1개를 기본 한도로 삼고 전체 8개를 넘지 않습니다. 파생 개념의 구성 요소와 명시한 Fog/Volume/Shafts 조합을 유지할 때 분위기 한도에 예외가 있습니다. 점수는 제작 규칙의 순위이며 성공률이나 물리 시뮬레이션 값이 아닙니다.

Rim, Micro Imperfection, God Rays는 독립적인 공식 기능으로 선언하지 않고 파생 구성으로 표시합니다. 필요한 광원·표면·매질 카드도 함께 선택합니다. SSS와 Transmission, Bump와 Displacement, DOF와 Bloom처럼 혼동하기 쉬운 역할을 구분합니다.

## 출력과 시간

간결 영문은 60~100단어의 요약입니다. 상세 영문은 명시한 출력·보존 조건과 선택한 지시를 포함하며, 예제는 120~180단어입니다. 사용자 조건이 길면 상세 프롬프트도 길어질 수 있습니다. 필요 조건을 원문 목록으로 별도 보관하므로 생성 서비스에 넣기 전 함께 검수합니다.

5단계의 상대 시간 비율은 검수용 편집 계획입니다. 정확한 프레임이나 탄젠트는 추정하지 않습니다. 제공한 곡선 값에 없는 오버슈트·반동은 곡선 번역에 추가하지 않습니다.

## 실행 경계

외부 네트워크, 모델 호출, 자산 파일 읽기, 영구 DB 생성은 없습니다. `composer_schema.sql`은 메모리 SQLite의 실행 추적에만 사용합니다. 원본 지식 SQL과 연결하지 않습니다. 소스 해시는 실행 전후에 비교하고, 결과에는 개인 설치 경로를 넣지 않습니다.

CLI가 쓰는 파일은 사용자가 `--output`으로 요청한 결과뿐입니다. 기존 결과는 덮어쓰지 않습니다. 검사기는 검사용 임시 폴더를 만들고 정리하며, 사용자가 가진 DB·미디어를 삭제하지 않습니다.
